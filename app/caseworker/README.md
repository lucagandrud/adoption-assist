# /app/caseworker — packet review

The second surface. Deliverable **D7**, phase hours 16–19. Cut #3 if behind.

The caseworker receives the assembled packet **with all automated checks already run**,
reviews it, exercises judgment, and submits.

## What this surface must show

- The assembled family-side packet
- Every Engine 1 defect, with both conflicting sources and the rule's citation
- Every Engine 2 expiration risk against the 180-day clock, with renewal deadlines
- **Every interview-sourced field, flagged for human review** — anything with provenance
  `interview` is a draft the caseworker edits, never a finalized value
- Verification status on every requirement; `verified: false` entries badged as unverified

## The value proposition, concretely

Caseworkers spend 4.3 hours of every 8-hour day on documentation (OPRE, July 2025). This
surface exists to return some of that time — the checks a human would otherwise perform by
eye are already done and traceable when the packet arrives.

That is the defensible cost-reduction claim, and it rests on a federal source.

## What this surface must never do

**No substantive assessment.** The home study narrative is a clinical judgment made by a
licensed social worker. This screen presents completeness, consistency, validity, and
sequencing findings — it never scores a family, ranks a family, or recommends approval or
denial. (Hard boundary #1.)

If a family is genuinely unsuitable, the human process must still catch that. **We must not
obscure it.** A UI that reads as "all checks passed" invites exactly that failure — frame
findings as *paperwork status*, never as *clearance*.

## Framing

Decision-support for caseworker review, not an approval decision. (Hard boundary #5.)
