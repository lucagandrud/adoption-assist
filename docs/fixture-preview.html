The dependency graph

nodes[] · edges[] · critical_path[]

Arrows are edges[] — they say what blocks what. The orange path is critical_path[]: the chain with zero slack, where any delay pushes the filing date. Nothing here is hand-positioned; the layout comes from the edges.

Node states

nodes[].state
"locked" Blocked upstream

Something it depends on isn't finished. Dimmed, not actionable.

"in_progress" Partly done

Some inputs uploaded, others still missing.

"verified" Paperwork consistent

All inputs present, all checks passed. Never means the family is approved.

"defect" Contradiction found

Outranks verified — a node with every input present still can't read as done.

Field reference

top-level keys
KeyWhat it is
caseWhich case, which two states, which direction, and the family profile that decides which requirements apply.
nodes[]One per requirement. Carries its label, state, inputs, citation, and any defects.
edges[]Dependencies — from blocks to. The graph layout is derived from these, never hand-drawn.
critical_path[]The zero-slack chain. Delay any of these and the filing date moves.
earliest_filingSoonest the packet can go out, computed from how long each document takes to obtain.
nodes[].inputs[]The documents or facts that satisfy a requirement, each flagged satisfied or not.
nodes[].citationThe regulation behind the requirement. Shown in the UI — it's what makes this more than a checklist.
nodes[].verifiedWhether the citation is sourced. false renders an Unverified badge.
Everything above is placeholder structure, not real regulation. Every citation in the fixture reads PLACEHOLDER and every entry is verified: false on purpose — Christopher replaces them with sourced California and Texas requirements. The shape is what's being agreed here, not the content.
